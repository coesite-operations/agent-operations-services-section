# Consulting Obsmetrologia

Obsmetrologia is not a small reference: as of this skill's writing its Verso
manual alone (`docs/verso/ObsmetrologiaManual/`) holds thousands of files
organized into Books and Parts, each a machine-checked Lean development. Its
own root `CLAUDE.md` states the rule this skill exists to enforce: **"Read the
indicated corpus node first... Never guess from a slug. One read of the named
file beats ten skimmed neighbours."** This skill is what lets a session honor
that rule without loading the whole corpus into its own context.

Root: `lib/emsenn/services/561-group/services/lenticule-science/services/obsmetrological-services-section/src/services/obsmetrologia`

## Where to look, in order

1. **The corpus's own agent-facing index first** — `.agents/docs/references/`
   holds a concept atlas, coverage report, and term ledger per topic
   (articulation, calculus, closure, cohomology, computing, dynamics, ...),
   plus `coverage-index.md` and `concept-glossary.md`. This is the fastest
   path to "does Obsmetrologia have X, and where."
2. **The verses** — `docs/verso/mark/content/` is the generative corpus
   itself: the directory path *is* a Curry–Howard proof, each segment
   generated by the one before it (spine: articulating → predicating →
   positing → settling). `docs/verso/ObsmetrologiaManual/Book*/` is the
   rendered manual built from it. Open the exact `<slug>/<slug>.md` node
   named by the question — plus its `references/` and `explanations/`
   siblings — never a neighbour guessed from the slug.
3. **The Lean development** — `Obsmetrologia/*.lean` is the machine-checked
   proof itself. `.mcp.json` in this package registers the
   `obsmetrologia-lean-lsp` MCP server (a `lean-lsp-mcp` instance scoped to
   this package): use its diagnostics/term-goal/hover/outline tools for a
   question about what is actually proved, what a declaration's type is, or
   whether a result is axiom-free, rather than trusting a doc's prose claim
   about proof status. `#print axioms <thm>` is the ground truth for "is this
   proved without hidden assumptions."
4. **Prior NotebookLM consultations** — `notebooklm-notes/` holds notes
   already produced from prior NotebookLM sessions against this corpus
   (e.g. `dervish-chu-space-connection.md`). Check here before asking a new
   question that may already have been asked.

## Escalating to NotebookLM for synthesis

The above four steps are deterministic reads and answer most questions. If a
question needs synthesis across many verses rather than one exact node — the
same shape of escalation `searching-union-notebook` uses for the Union
corpus — this corpus does not yet have its own pinned advisory-corpus
manifest or adapter script (there is no `obsmetrologia-advisor.mjs` beside
`union-notebook-advisor.mjs`). Opening a live NotebookLM workspace over this
corpus is a metered, authorization-gated act — `observe_notebooklm_market`
states plainly that "a purchased workspace offer does not create Leader
authority; live opening also requires a current exact notebook-creation
authorization" (see
`lib/emsenn/services/561-group/services/red-cup-engineering/services/inference-services-section/services/notebooklm-inference-team/src/notebook-creation-authorization-client.mjs`).
Report that an Obsmetrologia advisory corpus does not exist yet as a named
gap, the same way `content-librarian` reports an absent term, rather than
opening a paid workspace on this skill's own authority.

## Reporting back

State what was actually read (exact file paths), quote or closely paraphrase
the sourced passage, and if the corpus does not settle the question, say so —
`content-librarian`'s own rule applies here too: answer that the corpus does
not define something rather than inventing an answer that sounds like it
belongs in a formal-math manual.

## When NOT to use

- For a question about Obsmetrologia *applied* to a financial method — that
  is `quantitative-methods-lead`'s lane, not this skill's.
- For editing or extending the Lean development — this skill only reads.
