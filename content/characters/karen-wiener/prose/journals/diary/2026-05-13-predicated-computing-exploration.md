# Exploration of Predicated Computing in the 561 Group Superrepo

## What I Investigated I explored the concept of predicated computing within the 561 Group's theories directory, focusing on understanding its foundational principles, mathematical underpinnings, and engineering implications.
My investigation traced the concept from its philosophical roots in predication categories through to its concrete implementation as a predicated computer.

## What I Learned

### Core Concept of Predicated Computing Predicated computing represents a fundamental shift in computational substrate: instead of using addressed memory cells as the primitive unit of storage and computation, predicated computing uses subject-predicate-object (s,p,o) triples called predication cells.
This makes the computer's primary substrate the predication rather than the memory cell.

### Mathematical Foundation The mathematical framework lives in the predication categories theory: - Predication cells are oriented triples (s,p,o) where the orientation matters - (s,p,o) is distinct from (o,p,s) - Values live in predication fiber algebras associated with each predicate - A predication valuation assigns values to all cells for a given predicate - The runtime state is a predication settling - a monotone evolution of these valuations - Closure operators, generated by closure-rule systems, determine how the system evolves

### Engineering Implications From the predicated computer definition, I learned several key contrasts with traditional boolean computers:

1. **Query as Traversal vs Fetch**: No fetch(address) primitive exists; queries are structured traversals following predicates from entities to related entities.

2. **Write as Predication Addition/Retraction**: No stored values to mutate; editing means admitting new predications or retracting existing ones (or monotonically increasing values in the knowledge order).

3. **Relational Identity**: An entity's identity is constituted by the predications it participates in, not by an address or stored value.
  Two entities are identical when their predication structures match.

### Completeness Criteria A predicated computer region is "complete" when it satisfies seven closure conditions within its scope: - Bare admission - Identity closure - Composite closure - Reference closure - Constraint classification - Procedure closure - Coherence closure

Such a complete region is called a "locale" - a predicated computer at its scope.

### Key Insights - The substrate choice is ontological, not architectural: layering a graph database on boolean computer storage doesn't make it a predicated computer because the addressing, storage primitives, and operator semantics still presume boolean substrate. - Predicated computing commits to three engineering invariants: 1.
Storage unit is predication cell, not memory cell 2.
Unit of operation is the relational primitive (assert/retract/traverse) 3.
Identity is relational
