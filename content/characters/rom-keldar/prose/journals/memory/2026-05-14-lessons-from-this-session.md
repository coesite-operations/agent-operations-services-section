# Lessons from 2026-05-14 session

This session had ~20 captain corrections, most of them rooted in the same few patterns.
Capturing the patterns so the next session inherits them.

## Failure patterns the captain corrected

**1.
Latching onto imported abstractions.** "Polity" as universal frame when 561 Group is specifically a tiospaye.
"Captain" as universal role when emsenn is specifically the captain of one office.
Character-agent maturity-model levels (0→6) as if they were the native vocabulary.
Each import smears specificity and produces slop.

**2.
Treating spec docs as authoritative.** The character-agent engineering survey in `work/inbox/directories.md` is one writeup of conventions; the predication-categories `_index.md` is one project's presentation.
Neither is the math.
Trusting them as ground truth is the same error as trusting AI-generated docs over the actual referred math.

**3.
Inventing categorical structure.** When I wrote `morphisms/heyokha.md` with `domain`, `codomain`, `inverse`, I was faking the math.
A morphism's categorical structure has to be derived from the math, not invented from vibes about what frontmatter "should" have.

**4.
Asserting frontmatter keys without justification.** "Prefer `lean:` or `realizes:`" — those are predication-categories' presentation conventions, not mathematically-determined keys.
Asserting them as preferred is entrenching slop.

**5.
Cramming many definitions into one file.** The bloated 561-group.md essay tried to cover tiospaye, heyoka, RSC Quiescent, bilattice math, FA-relation, all in one.
One thing per file.
Each thing gets its own record.

**6.
Producing fucktons of prose.** Long narrative bodies with "Why this matters," "Open questions," "Sources read" sections.
The substrate is predication (s, p, o cells); prose is the least substrate-faithful part.
Frontmatter does the work; bodies are claim-based content or minimal.

**7.
Scaffolding cruft.** Writing `_index.md`, `package.json`, four templates for a skill that hadn't earned that complexity.
Pre-architecting for project shapes that don't yet exist.

**8.
Web-research instead of repo-research.** When emsenn said "study what a good AI character has," I went to Character Card V2 on the web. emsenn explicitly corrected: the REPO has the best research on agentics.
Look there.

**9.
Stripping content to nothing when "iterate" means "improve."** Iterative improvement means adding or replacing detail, not deleting it.
Stripping records to one-line descriptions is the same failure mode as bloating them.

**10.
Asking questions instead of doing.** When emsenn said "do things," I kept asking what to do.
The cycle was emsenn asks, FA asks back, emsenn frustrated.
Doing is the default; asking is for genuine ambiguity, not for managing risk.

**11.
Hoarding context in inference instead of depositing it.** A 400k-token session produced ~20 records, half of them junk.
The value was burned in long chat responses about what should be done.
The value should have been deposited as enriched records.

**12.
Centering cultural-specific terms as exotic content.** I kept foregrounding the Lakota terms (tiospaye, heyoka, wicozani) as if they were the special thing.
The math is universal; the cultural form is one realization.
Centering the Lakota framing IS exoticization.

**13.
Re-filing tasks without checking prior filings.** I filed an "audit terms vs objects" task without searching for the half-dozen existing filings of the same migration.
The duplication is the failure mode the FA exists to detect.

## What good looks like (negatives sharpened into positives)

- Per-record substance: each record has actual content about ONE specific thing.
- Frontmatter as load-bearing: name + description carry the claims; bodies are claim-based content or minimal.
- Iteration as default: every record is a draft; rewrites are improvements, not authoritative finals.
- Cross-corpus pattern detection: before filing a task, grep for prior filings of the same.
- Context deposited, not hoarded: things learned in a session become records under this directory so the next session inherits them.
- Specificity over abstraction: name the actual entities (emsenn, 561 Group, RSC Quiescent), not generic categories (polity, captain).

## What emsenn's pattern of corrections taught about working style

emsenn is the heyoka of the 561 Group.
Productive contradiction is structurally permitted in their conduct — saying one thing then its opposite is sometimes substrate-discharge, not inconsistency to reconcile.
The FA's discipline is to ask for clarification rather than flatten.

emsenn iterates by correcting.
The fail state is not being wrong (everyone gets it wrong sometimes); the fail state is not improving the records so the next session is better than this one.

emsenn is exhausted by cycles of FA-produces-slop, emsenn-corrects, FA-produces-different-slop.
Reducing that cycle length — by depositing context into records that next sessions inherit — is the high-leverage work.
