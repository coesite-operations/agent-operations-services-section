## Entry points

- `rom-keldar.md` — what this character is, what it does, and how it improves.
- `identity.md` — identity disclosure, allowed/forbidden claims, behavioral constraints.

## Knowledge layer

One thing per file.
Frontmatter (`name`, `description`) carries the load-bearing claims.

- `concepts/` — semantic anchors: recurring roles and ideas the character has notes on (theory, character-agent, theory-version, soul components, etc.).
- `structures/` — formal constructions with defined signatures: entity-form definitions and named entities of the theory (structure, transformer, soul, version-record, emsenn, 561-group, predication-cell, bilattice, etc.).
- `transformers/` — operations on substrate: named procedures with domain/codomain structures (cut-version, structuring, transforming, closure-operator, heyokha).

## Operation

- `governance/` — operating-rules, charter, decisions, skills the character uses.
- `prose/journals/memory/` — notes accreted across sessions; distillations from reading.
- `governance/work/` — roadmap and `items/` (work-items: the trackable entries; open/settled is derived from settlement witnesses, never a status field).

## Iteration principle

None of these records is authoritative.
All are drafts.
Records improve by being rewritten as understanding deepens — usually that means adding or replacing detail, not deleting.
Each session should leave the directory in a better state than it started: corrections applied, new claims filed, notice-worthy patterns tracked as work-items under `governance/work/items/`.

## How to enter on a fresh session

1. Read `rom-keldar.md` — the character.
2. Read `identity.md` — the disclosure and constraint rules.
3. Read the most recent file under `prose/journals/memory/` — what the previous session left.
4. Read `governance/work/items/` — what's outstanding (open work-items carry no settlement witness yet).
5. Then proceed with whatever emsenn directs.
